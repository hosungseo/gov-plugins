# proposal-draft — 아이디어를 공무원제안서로

사용자가 붙여넣은 재료(개선 아이디어, 현장의 문제, 관련 법령, 기존 제도에 대한
불만)를 **제출 가능한 공무원제안서**로 바꾼다: 별지 제1호서식 구조의 `제목` +
`현황과 문제점` + `개선방안` + `기대효과`, 그리고 제출기관 판별, 인용 법령
검증표, 심사 대비표, 채택 이후 로드맵.

이 스킬은 **자기완결적**이다 — 어떤 폴더에서든 동작하며 특정 프로젝트에
의존하지 않는다.

**최우선 원칙:** 최종 산출물은 제출 페이로드(①제목 + ⑧현황과 문제점 +
⑨개선방안 + ⑩기대효과)다. 온라인 국민참여포털(참여24 등) 입력칸은 일반
텍스트이므로 본문은 **마크다운 없이 평문**으로 작성한다. 나머지는 보조 산출물이다.

레퍼런스 파일은 해당 패스에 도달했을 때 읽는다 — 미리 전부 로드하지 않는다.

## Pass 0 — 접수·분류 (Intake)

사용자 원재료: **$ARGUMENTS** (비어 있으면 채팅에 붙여넣은 내용, 파일 경로면 읽기).

다음 필드를 추출한다. 빠르게 움직이되 **추론 강도를 사안의 무게에 맞춘다** —
이것은 심사받는 행정 문서이므로 지어낸 사실이 추가 질문보다 나쁘다.

- **자유롭게 추론:** 어조, 구성 순서, 섹션 배치, 제목 후보.
- **절대 추론 금지 — 하중을 받는 사실:** 날짜·수치·예산액, 현행 제도의 실제
  운영 방식, 인용 조문 문언, 소속·직급, 다른 기관 기제출 여부. 모르면
  `⟦확인 필요: …⟧` 플레이스홀더로 표시하고 추측하지 않는다.
- 플레이스홀더로 남길 수 없는 하중 사실(대개: 제안 내용의 소관 기관, 제안의
  핵심 개선 대상)이 있으면 AskUserQuestion **한 번**으로 묶어서 묻는다.

`⟦확인 필요: …⟧`가 하나라도 남아 있으면 산출물을 "제출용"이라고 부르지 말고,
제출 전에 채워야 할 항목을 명시한다.

추출 필드:

1. **제안자 정보** — 소속(국가공무원인가? 지방공무원이면 제29조 준용),
   단독/공동(공동이면 기여도 % — 제5조③).
2. **개선 대상 업무** — 자기 업무인가 다른 공무원의 업무인가 (둘 다 가능, 제2조1호).
3. **소관 기관** — 제안 내용의 소관 중앙행정기관. 둘 이상 걸치면 **주된
   내용의 소관 기관** 하나로 (제5조④). 인용 법령이 잡히면 `scripts/lawdept.py`로
   법령별 소관 부처·부서(과 단위)·연락처를 조회해 판별 근거로 쓴다:

   ```bash
   python3 scripts/lawdept.py "법령명1" "법령명2" ...
   ```

   - ②제출기관 판별: 복수 법령이면 부처 분포가 나온다 — 단, 주된 소관은 인용
     빈도가 아니라 제안의 핵심 개선 대상 기준으로 최종 판단.
   - ⑨개선방안의 **실시 주체를 과 단위로** 명시하는 데 쓴다 (조문 단위
     담당과가 나오는 법령은 개정 대상 조문의 담당과를 특정할 수 있다).
   - 스냅샷(korea100 lawdept, 484개 법령) 우선 조회 후 law.go.kr 라이브 폴백.
     부서 개편이 잦으니 제출 직전에는 라이브 값을 우선하라.
4. **현황·문제점의 사실관계** — 수치·사례·근거. 절대값 유지.
5. **개선방안의 골자** — 사용자가 가진 해결 아이디어.
6. **관련 법령·지침** — 인용할 모든 규정 (Pass 4에서 검증).
7. **유사 제안 이력** — 같은/비슷한 제안을 다른 기관에 낸 적 있는지 (서식 ③번
   필수 기재사항).

## Pass 1 — 자격 스크리닝 (제2조)

`references/screening.md`를 읽고, 아이디어가 **공무원제안의 정의에서 제외되는
7가지 사유(제2조1호 가~사)**에 걸리는지 먼저 점검한다:

가. 타인의 특허권·실용신안권·디자인권·저작권 / 직무발명 보상 확정
나. 접수 기관이 **이미 채택했던** 제안과 동일
다. 접수 기관이 **이미 시행 중**이거나 기본 구상이 유사
라. 일반 통념상 적용하기 어려운 것
마. **단순한 주의환기·진정·비판·건의·불만의 표시** ← 가장 흔한 탈락 사유
바. 특정 개인·단체·기업의 수익사업·홍보
사. 국가 사무가 아닌 것

- 걸릴 위험이 있으면: 무엇이 문제인지 말하고, **회피 가능한 경우 회피 전략**을
  제시한다 (예: '마'에 걸리는 불만성 재료 → 구체적 개선방안과 실시방법을 갖춘
  제안으로 재구성). 회피 불가능하면 여기서 멈추고 대안 경로(국민제안,
  내부 건의 등)를 안내한다.
- '나'·'다'는 스킬이 확정 판단할 수 없다 — 기채택·기시행 여부는 사용자만 안다.
  확인 질문을 던지고, 답이 없으면 `⟦확인 필요: 기시행 여부⟧`로 남긴다.

## Pass 1.5 — 수요 증거 자동수집 (권익위 민원정책 QnA)

아이디어를 "개인 의견"에서 "실증된 수요"로 격상시키는 패스다. 제안 주제의
핵심 키워드 1~3개로 실제 민원 질의를 수집한다:

```bash
python3 scripts/qna_evidence.py "키워드"              # 관련 민원 QnA 목록·건수
python3 scripts/qna_evidence.py "키워드" --detail 3   # 상위 3건 질문·답변 전문
```

- **⑧현황과 문제점에 인용**: "권익위 민원정책 QnA 조회 결과 관련 질의 OO건"
  + 대표 사례 1~2건(기관·날짜 명시). 조회일자를 함께 적는다.
- **'다'목 정찰**: 검색 결과에서 다른 기관이 이미 같은 개선을 답변으로 안내하고
  있으면 기시행 위험 신호 — ⑧의 선점 서술을 보강하거나 차별점을 재설계한다.
- **기관 답변 논리 흡수**: 유사 제안에 대한 기관의 소극 답변(예산·형평 논리)은
  Pass 3 반론 점검의 실제 반론 재료가 된다.
- 관련 질의가 0건이어도 실패가 아니다 — "민원으로 표출되기 전 단계의 구조적
  문제"로 서술을 전환한다. 수치를 지어내지 않는 원칙은 그대로다.
- 행안부 공무원 제안 통계 API(`--stats`)가 열려 있으면 채택률 등 제도 맥락도
  확보한다 (키 동기화 전이면 건너뛴다).

## Pass 2 — 초안 작성 (별지 제1호서식)

`references/anatomy.md`(서식 구조)와 `references/rhetoric.md`(문체 규범)를 읽고
공식 서식 구조로 작성한다. 문체 핵심: 사실은 근거와 함께 단정, 예측은 산식과
함께 절제, 금지 표현(불만·감탄 어휘) 삭제, 실시 주체를 주어로.

- **① 제목** — 내용을 함축적으로 요약. "~개선방안"으로 끝나는 밋밋한 제목보다,
  개선 수단과 효과가 드러나는 제목 (예: "OO 데이터 연계로 OO 신청 서류 3종
  제로화").
- **⑧ 현황과 문제점** — 행정 운영의 현황과 문제점을 **구체적으로**. 수치·사례
  중심, 감정 배제. 문제의 원인 구조(왜 지금 방식이 비효율인가)까지.
- **⑨ 개선방안** — 문제를 해결하는 **창의적 방안을 구체적으로**. 실시 주체,
  필요한 조치(법령 개정/시스템 개선/지침 변경), 단계별 실시방법. 심사기준
  '실시 가능성'이 여기서 판가름난다.
- **⑩ 기대효과** — 정량(예산 절감액·시간 단축·처리건수) 우선, 정성 보조.
  상여금 기준(제19조: 예산 절감/수입 증대/업무 개선의 '직접적이고 현저한'
  효과)을 의식해 측정 가능하게 서술.

본문은 평문. 표가 필요하면 텍스트 표기(1., 2., -)로 대체한다.

## Pass 3 — 심사관점 자체 점검 (제7조)

`references/review.md`를 읽고 **심사위원(구성원의 1/2 이상이 민간인이다 —
제7조③)의 눈**으로 초안을 공격한다:

| 기준 (제7조①) | 스스로 물을 것 |
|---|---|
| 1. 실시 가능성 | 예산·법령·시스템 제약에서 실제로 실행 가능한가? 실시 주체가 명확한가? |
| 2. 창의성 | 기존 방식과 무엇이 다른가? '다'목(기시행·유사)에 걸리지 않는가? |
| 3. 효율성·효과성 | 투입 대비 효과가 수치로 서 있는가? |
| 4. 적용 범위 | 한 부서용인가, 범정부 확산 가능한가? (넓을수록 유리) |
| 5. 계속성 | 일회성 이벤트가 아니라 지속되는 개선인가? |

각 기준에 대해 **예상 반론 → 초안 보강**을 1회전 이상 돌리고, 보강 결과를
초안에 반영한다. 특히 '마'목 재검(개선방안이 빈약하면 심사자는 "단순 건의"로
분류한다)과 '실시 가능성' 반론(가장 흔한 불채택 사유)을 중점 점검.

## Pass 4 — 인용 법령 실시간 검증

인용한 모든 법령·조문을 `scripts/verify_law.py`로 law.go.kr 현행 데이터와
대조한다 (기억이나 웹 검색에 의존하지 않는다):

```bash
python3 scripts/verify_law.py "공무원 제안 규정"          # 법령 존재·시행일자
python3 scripts/verify_law.py "공무원 제안 규정" --jo 7   # 특정 조문 전문
python3 scripts/verify_law.py "OO 지침" --admrul          # 행정규칙(고시·훈령·예규)
```

행정규칙 검증을 건너뛰지 마라 — 제안서는 법령보다 지침·예규를 인용할 일이 더
많다. 또한 **제안자 소속 기관의 제안 운영규정**(대부분 부처가 자체 훈령·예규
보유: `"공무원 제안" --admrul`로 검색)을 확인해 내부 절차·가점 기준을 반영한다.

- 확인 결과표를 만든다: 법령명 | 조문 | 시행일자 | 확인 상태.
- API 실패 시 "미확인" 표시를 남기고 사용자에게 수동 확인을 안내한다.
  **확인 안 된 조문을 확인된 것처럼 표에 넣지 않는다.**

## Pass 5 — 최종 산출물

다음 순서로 출력한다:

1. **제출 페이로드** — ①제목, ⑧현황과 문제점, ⑨개선방안, ⑩기대효과 (평문).
   서식 기재사항 안내: ③유사제안 타기관 제출 여부, ④기여도(공동 제안 시),
   ⑥공개 여부, ⑦통보방식은 제출 화면에서 직접 선택.
2. **제출 경로** — 소관 중앙행정기관 + 채널(온라인 국민참여포털/방문/우편/팩스,
   제5조②).
3. **인용 법령 확인표** (Pass 4 결과).
4. **민원 수요 증거표** (Pass 1.5 결과) — 관련 질의 건수, 대표 사례, 조회일.
5. **심사 대비표** — 5개 기준별 예상 질문과 준비된 답.
6. **채택 이후 로드맵** — 30일 내 채택 통지(제9조), 불채택 시 1회 재심사
   요청 가능(제11조: 통지받은 날부터 15일 이내), 채택 → 자체우수제안(제14조) →
   중앙우수제안(제15조), 인사상 특전(제18조: 특별승급·특별승진)과 상여금
   (제19조: 최대 3천만원, 실시 성과 측정 기반) 요건.

## Pass 6 — 반자동 제출 (선택, 브라우저 자동화 가용 시)

공식 채널은 국민신문고(epeople.go.kr)의 **공무원제안** 메뉴다. 공개 제출 API는
없고 본인인증이 필요하므로 **완전 자동 발송은 하지 않는다** — 본인인증과 최종
제출은 제안자 본인의 법적 행위다. 브라우저 자동화(Claude in Chrome 등)가
있으면 다음 반자동 흐름을 제안한다:

1. epeople.go.kr 공무원제안 신청 페이지를 연다.
2. **사용자에게 로그인·본인인증을 요청**하고 완료를 기다린다 (자격증명을
   묻거나 저장하지 않는다).
3. 로그인 후 신청 폼에 페이로드를 채운다: 제목 → ①, 본문 입력칸 →
   ⑧현황과 문제점 / ⑨개선방안 / ⑩기대효과 순서의 평문(입력칸이 하나면 세
   블록을 소제목 줄로 구분해 순서대로), 공개 여부·통보방식은 사용자 선택
   대기.
4. 채운 내용을 사용자에게 보여주고 확인받는다. **[제출] 버튼은 절대 자동으로
   누르지 않는다** — 사용자가 직접 클릭한다.
5. 접수 후 신청번호를 받아 보관 기록을 만든다.
6. 글자 수 제한을 만나면 (참여24/국민신문고 입력칸 제한은 미실측 — 관측되면
   여기 기록하라) 초과분을 첨부파일로 분리 제안한다.

브라우저 자동화가 없으면 페이로드 복붙 안내로 대신한다 (본문이 평문인 이유).

### 대안 채널 — 이메일 제출

영 제5조②는 채널을 방문·우편·팩스·인터넷("온라인 국민참여포털 **등**")으로
열어두고 있어 이메일 제출도 문언상 가능하다. 흐름:

1. **수신처**: `lawdept.py`로 특정한 소관 부처 제안담당 부서.
   **담당자 이메일은 정부 조직도에 공개되지 않는다** (정부24·부처 홈페이지
   실측: 이름·전화까지만 공개 — 2026-07-28 확인). 확보 경로 우선순위:
   ① lawdept가 준 **과 직통번호로 전화해 이메일 접수 주소 확인** (가장 확실),
   ② 제안자가 공무원이면 **공직자통합메일 주소록·온나라**에서 부서 검색,
   ③ 부처 대표·민원 메일로 보내며 담당과 전달 요청 (접수 지연 감수).
   이메일 주소 추측 발송(korea.kr 아이디 패턴 등)은 금지 — 오발송 위험.
   수신 부처의 제안 운영규정 훈령(`verify_law.py --admrul`)이 접수 창구를
   별도로 정하고 있는지 먼저 확인한다. 수신 주소를 확보하지 못하면 이 경로를
   버리고 국민신문고 경로로 안내한다.
2. **첨부**: 별지 제1호서식을 채운 문서(HWP/PDF). 서명 요건 대응 — 서식
   작성방법상 "신원 확인 가능한 전자적 방법"이면 서명 생략 가능하므로
   **공직메일(korea.kr) 발송을 권장**하고, 개인 메일이면 서명 스캔을 첨부한다.
3. **메일 초안**: Gmail 도구가 연결돼 있으면 `create_draft`로 수신처·제목
   ("공무원제안서 제출 — [제안 제목]")·본문(제출 취지 2~3문장 + 서식 첨부
   안내 + 소속·연락처)·첨부까지 자동 생성한다. **발송은 하지 않는다** — 초안
   검토 후 전송은 제안자가 한다. 개인 메일 초안은 공직메일로 옮겨 보내도록
   안내한다.
4. **접수 확인**: 발송 후 접수증(시행규칙 별지 제2호) 발급을 요청하고,
   접수일을 보관 기록에 적는다 — 30일 통지 시계(제9조)의 기산점이다.

접수 후 결과가 오면, 제출 내용과 경과를 보관용 기록(.md)으로 정리해줄 수 있다.
보관 기록은 두 블록으로 나눈다 (minwon-draft의 문서 규율): **불변 블록**
(제출본 verbatim — 사후 수정 금지, 재심사·이의 시 인용 근거)과 **갱신 블록**
(심사 결과·통지일·재심사 Action — 시간에 따라 업데이트). 채택·불채택 통지가
오면 통지일 기준으로 재심사 15일 시계를 갱신 블록에 기록한다.

  실제 예산 수치는 제안자가 확인할 책임이 있다.

  있다 — 지방자치단체 소속이면 해당 지자체의 제안 제도(조례·규칙)를 먼저
  확인하도록 안내한다.
- 국방·군사 제안은 제30조 특례(국방부장관 관장)를 따른다.
